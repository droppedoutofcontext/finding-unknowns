# finding-unknowns

**Мы плохо описываем, чего хотим. Но сразу узнаём, когда видим.**

Скилл для Claude Code на случай, когда промпт ещё не стал спекой. Вместо того чтобы угадывать,
Claude собирает маленькую интерактивную страницу. Ты показываешь, что нравится, а страница пишет
за тебя следующий промпт.

## Зачем

Агенты редко ломаются на написании кода. Они ломаются раньше: на промпте, в котором не хватает
требований, вкуса, краевых случаев или критериев ревью. Агент заполняет пробелы дефолтами и приносит
рабочий, но не тот результат.

> «Сделай посолиднее»  
> «Добавь шеринг, детали на твоё усмотрение»  
> «Перенеси как в референсе»  
> «Я готов это мержить?»

На вопрос «какой стиль хочешь?» человек пожимает плечами. Четыре отрисованных варианта он оценивает
мгновенно. Скилл тратит несколько дешёвых минут на такой показ до того, как начнётся дорогая сборка.

## Как это работает

1. **Показать.** Claude замечает, чего не хватает, и собирает один самодостаточный HTML-файл:
   варианты, мок, вопросы или квиз.
2. **Ткнуть.** Ты кликаешь то, что узнаёшь. Берёшь кусок, отбрасываешь кусок, выбираешь ответ,
   двигаешь слайдер.
3. **Вставить.** Страница собирает ответ по ходу кликов. Копируешь его в чат или отправляешь сразу,
   если хост это позволяет.
4. **Собрать.** Claude строит по принятым решениям и записывает их в `.unknowns/decisions.md`,
   чтобы решённое не спрашивать дважды.

Примеры на английском: скилл пишет артефакт на языке пользователя, так что в твоей сессии он будет
по-русски.

## Установка

Как плагин Claude Code:

```text
/plugin marketplace add droppedoutofcontext/finding-unknowns
/plugin install finding-unknowns@finding-unknowns
```

Или как обычный скилл, для любого рантайма, который читает `~/.claude/skills/`:

```bash
git clone https://github.com/droppedoutofcontext/finding-unknowns
cp -r finding-unknowns/skills/finding-unknowns ~/.claude/skills/
```

Дальше просто работай. Скилл срабатывает на расплывчатых или рискованных запросах, а ещё когда
спрашиваешь «что я упускаю?», «проинтервьюируй меня» или «проверь меня перед мержем».

## Когда срабатывает

Артефакт стоит нескольких минут, поэтому скилл сначала выбирает самый дешёвый способ снять
неизвестность:

| Ситуация | Что делает Claude |
|---|---|
| Ошибку дёшево переделать или некому ответить (headless, сабагент, CI) | Одной строкой перечисляет допущения и делает |
| Хватает одного–трёх независимых вопросов | Задаёт их в чате, без страницы |
| Ответ нужно увидеть, чтобы выбрать; много связанных вопросов; ты сам попросил интервью или квиз | Собирает артефакт |

«Исправь опечатку» страницу не получит. «Сделай лендинг солиднее» получит.

## Контракт артефакта

- Один HTML-файл на языке пользователя, без CDN, fetch и внешних зависимостей. Открывается из `file://`.
- Тихий интерфейс: цвет обозначает только твои решения. Стили живут внутри превью, а превью
  показывает решаемую вещь в её настоящем или предлагаемом виде.
- Каждый контрол обновляет собранный ответ. Кнопка копирования не врёт: если песочница блокирует
  буфер обмена, текст остаётся выделенным, и страница прямо об этом говорит.
- Перед выдачей скилл прогоняет верификатор без зависимостей:

```bash
node skills/finding-unknowns/scripts/verify_artifact.mjs path/to/artifact.html
```

## Работает ли это?

Небольшой набор эвалов: семь задач, по четыре бинарные проверки.

- **Позитивные (0–3)**, где скилл должен запустить цикл: **16/16** со скиллом и **3/16** без него.
  Это проверка следования процессу, а не качества итогового результата: без скилла артефактных
  проверок не пройти по построению.
- **Негативные (4–6)**, добавлены в 0.3.0: мелкая локальная правка, дешёвый UI-твик и фича с двумя
  независимыми вопросами. Здесь скилл должен не мешать. Цифр пока нет.

Протокол, фикстуры и дизайн outcome-эвала, который пока никто не прогонял в масштабе, лежат в
[`evals/`](skills/finding-unknowns/evals/). Прогонишь — открой issue с цифрами, в какую бы сторону
они ни указывали.
